# V1.1 Coverage, Copilot and Remediation Architecture

## Coverage Matrix

Coverage is deterministic and database-derived.

AI is not permitted to mark a coverage item as complete.

Each modeled area contains:

```text
key
label
category
status
weight
evidence_count
rationale
next_step
```

Score factors:

```text
covered      = 1.00
partial      = 0.50
needs_review = 0.35
gap          = 0.00
```

A `CoverageSnapshot` preserves each point-in-time assessment state.

## Analyst Copilot

Copilot has no execution capability.

Before provider invocation the backend:

1. rebuilds the redacted Knowledge Graph;
2. refreshes Assessment Memory;
3. generates a fresh Coverage Snapshot;
4. ranks relevant Graph/Memory/Coverage records using deterministic token overlap;
5. sends only the bounded structured context to the configured provider.

Allowed citations are generated by the backend.

Provider-returned citations outside this allowlist are rejected.

Unexpected execution-like output is counted as Copilot drift and discarded.

## Remediation

`FindingLifecycle` is a separate workflow entity instead of changing the legacy Finding schema.

This keeps historic Finding data compatible.

Workflow state does not alter vulnerability evidence.

## Retest

Retest reuses the Proof Capsule service.

There is no second validator implementation.

Network-backed retests continue to enforce the project's current Scope Engine.

Unsupported Finding sources remain manual-review capsules.

## Knowledge / Memory projection

Canonical Knowledge Graph stores workflow status but not remediation-note body.

Assessment Memory stores summary-level workflow state and repeat guidance.

This allows Copilot and specialist agents to reason about closure without receiving unrestricted analyst notes.

## Timestamp compatibility

The project stores UTC timestamps as naive SQLite-compatible datetimes.

V1.1 derives them from timezone-aware UTC values to avoid Python 3.13 `utcnow()` deprecation warnings.
