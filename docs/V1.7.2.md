# SnowEdge V1.7.2：统一产品命名

页面标题、设置、诊断、恢复、报告署名、请求 User-Agent、启动脚本、可执行文件元数据、文档与 Burp 扩展统一使用 SnowEdge。

正式启动入口为 SnowEdge.exe，配置文件为 SnowEdge.exe.config。原桌面工作台快捷方式更新为 SnowEdge，并指向新的可执行文件。根目录的旧启动器与调试符号移入 tools/dev/legacy，不进入正式发布包。

## 新文件与集成命名

- 新安装默认数据库为 snowedge.db。
- 新完整备份扩展名为 .snowedgebackup，格式标识为 snowedge-full-backup/1.6。
- 新脱敏项目包标识为 snowedge-project/1.6.2。
- Burp 扩展为 SnowEdge-Burp-1.0.0.jar，菜单显示 SnowEdge，鉴权头为 X-SnowEdge-Token。
- 表格与导航的浏览器设置使用 snowedge 命名空间，并读取迁移原设置。

## 旧工作区兼容

保留显式 DATABASE_URL 和原始配置、密钥、项目数据。没有显式数据库地址但存在旧数据库时，继续读取原文件，不复制运行中的数据库，不创建空项目替代旧数据。旧 APP_NAME 产品值在加载时归一化为 SnowEdge。

仍接受历史完整备份格式、历史脱敏项目包和旧 Burp 鉴权头。这些兼容标识以及第三方项目链接不作为当前产品名称显示。历史 QA、原工作目录路径和已有用户文件不批量改名。

Docker 新部署示例使用 snowedge 数据库与用户名。已有 PostgreSQL 数据卷不要重建；升级前在环境配置中明确保留原 POSTGRES_DB、POSTGRES_USER 和 DATABASE_URL。

## 验证

覆盖旧备份解密、新备份读写、新旧 Burp 请求头、旧项目包导入、新数据库默认名、旧数据库优先读取，以及编译后 Burp 类文件中的产品名称。旧数据测试使用临时文件与数据库，未修改用户实际数据库。
